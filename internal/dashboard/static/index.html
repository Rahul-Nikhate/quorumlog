Guided demo: kill the leader, lose nothing

Run the steps in order. Each button does one thing and tells you what happened. The dashboard remembers every message the cluster acknowledged, so step 7 can check that none were lost.

  1. Creates the topic through the replicated __meta group; every node opens a Raft group for it.

  2. Each message is acknowledged only after a majority (2 of 3) has it in its log.

  3. Stops the node that leads the topic's group. Its data directory is kept.

    Not in demo mode: stop the leader yourself, e.g. docker compose stop qlogd2. The dashboard watches for the change.

  4. Waits until the surviving nodes elect a leader with a higher term (see the event feed).

  5. Two of three nodes are still a majority, so writes keep working.

  6. The restarted node recovers its log from disk, then the leader sends it what it missed.

  7. Reads the topic from offset 0 and compares it with every message the cluster acknowledged.
